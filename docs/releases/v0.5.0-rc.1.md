# pkudisk-fuse v0.5.0-rc.1 (fork preview)

This Tim-1e fork preview adds native Windows background mounting and a Windows
service for mounting at boot. Fresh-machine and reboot acceptance are pending;
the preview is intended for that validation before an upstream proposal.

## Windows background mounting

```powershell
.\pkudisk-fuse.exe account add
.\pkudisk-fuse.exe mount P: --background
.\pkudisk-fuse.exe unmount P:
```

The background command returns after the drive is accessible. The same Go
executable continues with Windows `CREATE_NO_WINDOW`, so closing the terminal
does not stop the mount. There is one process per mount, without a launcher
script, helper executable or additional dependency. Startup errors return a
private log path; the default log is
`%LOCALAPPDATA%\pkudisk-fuse\background\P.log`.

The existing `mount P:` command still runs in the foreground. PowerShell's `&`
invokes a command and does not detach it. Background mode requires an unused
drive letter and a saved account; complete login/verification with `account add`
first. `unmount` waits for the normal filesystem and cache shutdown.

## Windows boot service

After saving an account, use an administrator terminal for installation:

```powershell
.\pkudisk-fuse.exe service install P:
.\pkudisk-fuse.exe service start
.\pkudisk-fuse.exe service status
.\pkudisk-fuse.exe service stop
.\pkudisk-fuse.exe service remove
```

Installation registers the native `pkudisk-fuse` service with delayed automatic
startup, a `WinFsp.Launcher` dependency and restart after an unexpected exit.
It runs as `NT SERVICE\pkudisk-fuse`, without storing a Windows password.
WinFsp supplies the service protocol and global drive mapping; the mount still
uses one Go process. The installing user can query, start and stop it without
elevation; installation and removal require administrator privileges.

The executable is copied below `%PROGRAMDATA%\pkudisk-fuse-service`. Selected
saved accounts, configuration, logs and cache use a separate, protected
`data` directory owned by the virtual service account. The original user store
keeps its existing permissions. Reinstall while stopped to update the binary
or refresh the service's account copy. Removal preserves accounts and cache
for recovery. Mount flags such as `--read-only` and `--root` apply at install.

## Installation and limits

Download the archive matching your OS and architecture from this fork's
[release page](https://github.com/Tim-1e/pkudisk-fuse/releases/tag/v0.5.0-rc.1)
and verify it against `checksums.txt`. Windows requires the
[WinFsp driver](https://github.com/winfsp/winfsp/releases/tag/v2.1); Go is not
required when using the archive. Linux/macOS mounting behavior is unchanged.
The Go module path remains `github.com/thezzisu/pkudisk-fuse`; this fork tag
is not an upstream Go installation version.

Use service and background mounting one at a time on a drive. Separate service
and user account stores do not share token-rotation locks, so avoid concurrent
mounts of the same account across these modes. Neither mode prompts for login
verification. Close applications using the drive before stopping or unmounting.

Validation on the development Windows machine covered actual hidden-process
mounting/unmounting, startup failure, duplicate mounting, private storage ACLs,
and repeated virtual-account service start/list/stop cycles. Ordinary-user
access to a service-mounted drive was verified. Six platform cross-builds,
vet and vulnerability checks passed. The full local Windows suite also exposed
an existing progressive-range-read test failure reproduced on unchanged
upstream code; publication remains gated on native three-platform CI. Reboot
and fresh-machine acceptance are left to the recipient of this preview.
